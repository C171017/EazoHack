## Minimum shared contract (version 1)

- Database `books.id` is a cloud UUID; `books.local_book_id` preserves the reader's existing `txt:<hash>`, `pdf:<hash>` or bundled ID. Do not replace `bookId` inside anchors/graphs/checkpoints with the cloud UUID. Map it at the boundary.
- `book_sources.file_hash` and `extraction_version` preserve existing anchor identity exactly. TXT import hashes original bytes and then normalizes CRLF to LF; therefore the normalized source object's digest may differ from `file_hash`. Put `sourceSha256` (SHA-256 of uploaded UTF-8 normalized text) in `manifest`, together with original hash/import manifest and normalization version. Never re-normalize on download or recalculate anchor IDs. PDF extracted text and original PDF retain their separate hashes/provenance.
- Source storage key: `<owner UUID>/<book UUID>/<source UUID>/source.txt`, plus optional `original.pdf`. Allocate UUIDs and insert metadata before uploading; upload with `upsert:false`. The worker must verify object existence, size and `sourceSha256` before starting. Missing uploads are pending metadata, not ready books. Clients cannot overwrite or delete original source versions; a new extraction requires a new source row/version.
- Preserve whole WorkspaceSnapshot payloads, validated by existing `WorkspaceSnapshotSchema` on export and import. Check every anchor/reader position against selected source hash/extraction version and the book mapping. JSONB shape checks only assert objects; they do not replace application Zod validation. Apply bounded request sizes before storing user JSON. Store large generated media privately through a separately reviewed media bucket before syncing such artifacts; do not persist expired provider URLs as durable media. This baseline persists current artifact JSON, not a media archival pipeline.
- Snapshot UUID must be stable across a retry; new saves use new UUIDs. Fetch by owner/book/checkpoint, ordered by server `created_at`, with a limit. Keep all device revisions; offer conflicting saves rather than overwriting silently. Stable device IDs are scoped to the installation; avoid collisions in events by namespacing `local_event_id` with book ID plus local sequence/event ID. Authenticated account caches must be account-scoped.
- Vercel dispatcher verifies identity, ownership, ready source, allowed pipeline/model and quota. It inserts a `queued` job using the secret client with `(owner_id,idempotency_key)` deduplication, then launches Cloud Run with **only `EAZO_ANALYSIS_JOB_ID`**. A reused idempotency key with a different payload must be rejected, not silently repurposed. The browser never writes a job or sees a worker credential.
- Cloud Run loads the job by UUID, calls `claim_analysis_job(p_job_id)` and exits harmlessly on zero rows. Claim returns a lease token, attempt and expiry. Heartbeat every 60 seconds using `heartbeat_analysis_job`; false means stop/abandon. Lease lasts 5 minutes. Reclaim of expired work issues a fresh token.
- Worker output prefix: `<owner>/<book>/<job>/<lease token>/`. Write `graph.json`, `hierarchy.json` and `manifest.json` with `upsert:false` to `eazo-analysis`. Each attempt has a different prefix, so a late worker cannot overwrite a newer attempt. Manifest records source identity, pipeline/model, graph version, content hashes and schema version. Run existing `GraphSchema`, `validateGraphSource`, `validateHierarchy` and axis consistency checks before calling `complete_analysis_job(p_job_id,p_lease_token,p_graph_version,p_manifest_sha256)`. It atomically publishes the graph row and succeeds the job only if the lease is current.
- Workers must not directly bypass the RPC publication protocol even though their service key can. Failure/cancel updates must use a compare-and-set on job ID, running status and current lease token, clear the lease, and set `updated_at`. Public error fields contain codes only, never prompts, book text, credentials or raw provider errors. Terminal jobs are not reclaimed; explicit retries create a new job/idempotency key.
- Dispatch can fail after DB insertion. A Cloud Run/Vercel-owned reconciliation mechanism must periodically dispatch queued jobs and expired leases. A database record alone is not a scheduler. Configure bounded retry/attempt caps and quotas in that integration; no scheduler is provisioned here.
- Owners can read job summaries and committed graph records. Storage reads allow only source objects or a published manifest/graph/hierarchy triple. Internal worker logs/chunks remain invisible. Use authenticated downloads or short-lived signed URLs (proposed 60 seconds), never public URLs. Signed URLs are bearer capabilities until expiry; don't log/cache/share them. [Private buckets](https://supabase.com/docs/guides/storage/buckets/fundamentals), [Storage RLS](https://supabase.com/docs/guides/storage/security/access-control).
- A future garbage collector removes abandoned attempt objects using Storage API after confirming no active lease/publication. Browser-local originals remain intact after any cloud export failure. Account sign-out cancels sync and clears only account-specific caches; never deletes the user's preexisting local library.
