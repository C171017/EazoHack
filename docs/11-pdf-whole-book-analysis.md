更新：2026-09-05。本说明记录用户范围、架构建议与只读实验；不代表整书生成、OCR 或服务部署已验收。

## 阅读与整书分析是两个任务

阅读器按需渲染附近页面、准备可选文字，用户可以先阅读。整书分析拥有独立的页/片段清单、进度、取消、重试与版本，必须处理读者未访问的页面。只处理当前页不能产生完整整书图谱；阅读就绪不等于整书分析完成。

两者复用相同来源与提取版本的缓存。记录至少包括文件指纹、页号、提取方法/引擎/版本、语言、文字、片段 ID、位置与可用置信信息。新提取结果另存版本，不能使已保存选文静默指向不同文字。

保留原 PDF。分析输入推荐为可定位的结构化文字，不要求一个丢失页码和版面的巨大 TXT。图片、空白页、无法识别的页均留清单；空 OCR 输出不能证明页面空白，文字提取完成也不能冒充图片语义分析完成。

## 提取顺序的纠正

1. 优先使用内嵌文字及几何位置，无需 LM 重抄。
2. 空格、分行或顺序异常时，先检查提取器和间距重建。粘连输出不充分证明 PDF 文字层损坏。
3. 确认文字仍不可用或缺少时才 OCR 对应页面；保存原结果、位置与置信信息，低质量结果标记待检查。
4. 双栏、边注或标题层级仍不明确时，可选 LM 提议阅读顺序/结构。原始文字与 OCR 保留，派生整理不悄悄删改引文。

## 模型可以直接接收 PDF

支持多模态 PDF 的 API 可以内部处理页面图像和提取文字，应用不必先转全书 TXT。[Claude PDF 文档](https://platform.claude.com/docs/en/build-with-claude/pdf-support) 描述了此流程。不能以“模型只接受纯文本”作为架构前提。

直接 PDF 输入仍受页数、文件大小与上下文限制；须核对所选接口并记录提交范围。2026-09-05 查到的 Claude 文档列出最高 600 页/请求（小于 1M 上下文时为 100 页），本地 628 页版本需拆分。此例不构成模型选择，限制可能变化。

推荐保留自己的可定位文字，便于搜索、多轮生成、引用验证与回原文；疑难版面或非文字内容补充原页图像。直接 PDF 模型输出的引用同样须解析与验证，不能信任模型编造页码/偏移量。

## 章节与 Preview 目录

[Apple Preview 文档](https://support.apple.com/en-gb/guide/preview/prvw11470/mac) 说明显示来源自带目录（如果存在），不是自动理解任意书籍的保证。[PDF.js getOutline](https://mozilla.github.io/pdf.js/api/draft/api.js.html) 可读取内嵌大纲。本地 Republic PDF 检查结果为 0 个大纲顶层条目。

有大纲则核对目的页；无大纲则结合印刷目录、提取标题与版面线索提出章节边界，再核验页面。区分印刷页码与 PDF 页索引。章节帮助分块，不能代替读取正文；无章节也可按页/长度分块。前言、边注、索引应保留并标明来源角色，避免把编者评论当作对话正文。

## 建议的图谱流水线

1. 建立完整页/片段清单及章节边界，保留识别依据。
2. 按章节或长度读取实际内容；长章节再分块，重叠沿用原片段 ID。
3. 模型生成概念/关系候选并引用已存在的证据片段。名著先验知识可提出待查假设，不能填补未读内容。
4. 跨块合并同一概念，保留各次出现；用原文证据核对跨章关系，不能只根据压缩摘要建立事实。
5. 按 [3D 契约](08-book-map-3d.md) 计算空间：模型可提议主题与结构层级，来源进度从真实出处计算，坐标受应用规则约束。PDF 来源顺序解析仍须实现/验证，不直接套用 TXT 字符偏移公式或由模型猜位置。
6. 逐步显示已校验结果，分别呈现提取与分析进度；失败、未处理页及未覆盖非文字内容不得隐藏在“整书完成”中。流程覆盖也不保证每个概念提取正确。

建议全量 OCR/分析使用有界并发、可恢复任务与持久缓存。不能假设一次 Route Handler 请求可无限运行。浏览器按需 OCR 是阅读路径，不应当作低耗电整书扫描方案；外部整书上传、执行位置与 provider 仍须按最终选择接入。

## 工具候选与评估

| 用途 | 候选 | 依据/取舍 |
| --- | --- | --- |
| 页面显示与内嵌文字 | 已有 PDF.js | 符合现有阅读栈；不是 OCR 或完整语义分析 |
| 原生文字/几何提取 | [pdfplumber](https://github.com/jsvine/pdfplumber) | 本次抽样有依据；仍需评估顺序，并非 OCR 引擎 |
| 托管 OCR 与结构提取 | [Mistral Document AI OCR](https://docs.mistral.ai/studio/document-processing/basic_ocr) | 支持结构化内容和段落框；需实测旧版书、核对数据发送、费用、限制与回链精度 |
| 本地/指定机器版面处理 | [Docling](https://docling-project.github.io/docling/reference/pipeline_options/) | 支持内嵌提取、可配置 OCR 与流水线；依赖/算力成本高于简单提取 |

以上为候选，不新增锁定依赖或服务。先抽样正文、目录、索引、边注和较差扫描页，比较字词、顺序、位置与耗时。厂商吞吐量不等于用户单本书端到端延迟。伴随 Gutenberg TXT 与 PDF 不是同一字节/位置来源，未经对齐不得互换。

## 衔接验收

- 未访问页仍进入整书清单；当前页可选不使全书标 complete。
- 正常内嵌文字不触发 OCR；提取造成的间距异常先检查提取方式。
- 缺页、低质量文字、无文字图片分别记录，不静默丢弃。
- 图谱节点和边返回原页及真实证据；编者评论与正文分开；模型先验不代替来源。
- 中断、重试、提取版本变化与跨章合并不丢出处；部分结果显示真实覆盖。
- 分别报告提取、OCR、分析测量；本次文档更新不构成实现验收。
